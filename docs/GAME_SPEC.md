# Hivee — ゲーム企画・仕様概要

> 更新日: 2026-11-24（初回プレイの流れを現行ソースで確認）  
> 情報源: 開発者がチャットで提示したゲーム構想。**ソースコードに実装されていることを保証する文書ではない。**  
> 用語: **構想**=開発者が目指す仕様、**確認済み実装**=ソースで直接確認、**未定**=詳細が決まっていない。

## 1. コンセプトと世界観【構想】

**Hivee（ハイビー）**は、リアルな地図を舞台にした、協力型の村育成ゲーム。

- 現実の地図にH3の六角形セルを重ね、神社・ランドマークなどを巡ってアイテムを集める。
- プレイヤー同士が協力し、**村ごとの精霊樹**を成長させる。
- 精霊が存在するファンタジー世界観。
- 個人キャラクターの成長よりも、**みんなで村を育てる**遊びを優先する。
- 村同士で資源を奪い合ったり、略奪したりするゲームにはしない。
- 他の村にも収集に行けるが、相手の資源を奪う行為ではない。

### 遊びの中心となる想定ループ【構想の整理】

ユーザーが本拠となる所属村を定める → 所有する妖精を旅先の村へ派遣する → 妖精が狩猟・採集し、重量制のカバンに素材を蓄える → ユーザーの所属村へ帰還して荷物を回収する → **ユーザー所有の重量無制限倉庫に保管する** → ユーザーが倉庫から任意の素材を手動奉納し精霊樹を育てる。倉庫の中身はユーザーが村を移籍しても持ち運べる。妖精を複数持つほど並行して収集できる遊びを目指す。

*これは開発者の説明を整理したもので、進行順序・UI・クエスト設計がすべて確定したわけではない。*

### ログイン後、最初の妖精を迎えるまで【確認済み実装】

1. 所属村がまだない場合、ログインすると `/world` で梅田の地図と「地図の色がついたマスを選んで、所属する村を決めましょう。」という案内が開く。「了解」を押すと地図を操作できる。
2. 色のついたマスを選ぶと、村名と「この村に入りますか？(移籍可能)」が表示される。村名が未設定なら地形名を表示する。右上の「×」で選び直せる。「入村する」を押して登録が成功すると、その村が地図の初期位置になる。村の人口・タイプの表示と、所属済みユーザーの移籍は今後の対応。
3. 所属村が決まり、所有妖精が0体なら、ワールド上にキャラクター選択画面がフェードインする。上部に見出し、左右に狩猟系・採集系の立ち絵、中央に選択用の紋章を配置する。最初は両方とも少し色を残したグレーで、紋章を選ぶと対応する妖精と紋章がフルカラーになる。
4. 16文字以内の名前を入力し、「このキャラクターで始める」を押す。同じ名前を使える。作成した妖精は所属村からスタートする。次回以降、所属村と妖精がそろっていれば、その村を中心に通常の地図が開く。

## 2. マップ・探索【構想】

- H3による六角形セルを地図に配置する。
- 原則として**全マップを航行可能**とし、海や山は移動コストを相当に高くする。
- セルごとに「開拓度」があり、繰り返し訪問すると通過係数が下がって移動しやすくなる。
- 行軍値・体力・仲間・装備なども移動に関わる構想。
- 特定の神社、ランドマーク、パワースポットなどに固有の報酬を置く構想。

**確認済み実装:** `resources/js/pages/world/` にMapLibreとH3の描画・選択処理がある。`villages` / `terrains` / `village_neighbors` にH3セル・地形・隣接情報の土台がある。**移動・開拓値更新・経路探索の完成は、このZIPから確認できない。**

## 3. ユーザーの所属村・妖精の滞在村・精霊樹【ゲーム方針確定／未実装を含む】

- **ユーザーがゲーム上の主体**。ユーザーはアカウントに対して**所属村（住民票・本拠）を1つ**決める。所属村が村チャットの所属判定・奉納先となる。
- **H3セル1つを村1つ**とする設計方針。初回入村できるのは地形の `terrains.is_developable` が真のセル。偽または未設定の村を選ぶと「この村は入村できません」と表示され、右上の「×」で選び直せる。居住可能な村ごとに精霊樹を設ける構想がある。
- **妖精（既存コードのCharacter）はユーザーに所有されるペット／派遣要員**。ユーザーの所属村にいる必要はなく、別の村に「滞在」して周辺で採集できる。妖精が滞在先を変えてもユーザーの所属村は変わらない。
- 妖精の滞在村はあくまで採集拠点。**滞在村の村チャットには参加できず**、その村へ素材を奉納する権限も得ない。
- ユーザー本人の移動にも妖精の移動にも**移動時間を設ける**。所属村の変更や移動時間の具体的処理は別途設計する。
- 村の移籍を「ユーザーの住民票の移動」として扱い、妖精の旅先への移動は「派遣・滞在・帰還」と呼ぶ（用語を分ける）。
- **ユーザー倉庫は村の設備・村共有物ではなくユーザー本人の所有物**。所属村を移籍しても倉庫の中身は同じユーザーに紐づいたまま移動し、素材が消えたり旧村・新村へ自動納入されたりしない。
- 村単位の精霊樹をみんなで育てる。村ごとの外観・デザイン、同盟・村人との交流も構想にある。村同士の略奪は主軸にしない。
- 妖精が滞在村を拠点として活用することへの**ボーナスは検討中**。内容や適用条件はまだ決めていない。

**現行コードとの違い:** 旧 `characters.village_id` は「所属村」として作られたが、今後は**妖精の滞在村として扱う方針**。新たな `users.village_id` をユーザー所属村の保存先として追加した。移動時間・滞在の切替・精霊樹の成長処理はまだ実装していない。

## 4. 妖精（キャラクター）【ゲーム方針確定／一部構想】

- `User` がゲームとチャットの主体であり、`Character` はユーザーに所有される妖精・ペット・派遣要員。
- 複数の妖精を保有して並行して採集することで、ユーザーの採集効率を高める。枠は**最大3枠**という既存案を維持する。
- 2枠目1,500円、3枠目3,500円、2・3枠セット4,500円は従来の**価格案**であり最終確定ではない。
- 狩猟妖精は収集時間を10%短縮、採集妖精はレア獲得率10%の恩恵という既存案を維持する（加算・乗算の詳細未定）。
- 妖精ごとに**重量制インベントリ**を持つ。遠征先で確認できるが、原則として遠征先では捨てたり、ユーザーへ荷物を引き渡したりできない。
- **荷物回収はユーザーの所属村への帰還後のみ**。カバンが満杯になったら荷を下ろすために帰還する。
- 課金特典として、遠征・派遣先でも妖精が所持品を廃棄できるようにする方針。具体的な価格・操作条件・誤廃棄防止は未定。
- 妖精の体力、移動時間、行軍値、同行などの従来の構想は残す。ユーザー本人の移動の扱いは別途設計する。

**コード整理（今回の未適用パッチ）:** 妖精を1体選んでユーザー主体とみなす `users.active_character_id` は廃止し、初期データで保有妖精一覧 `characters[]` を返す。`characters.text_id` はキャラクター宛DM専用だったため削除する。`characters.id`（内部参照）、`user_id`（所有者）、`slot`、`specialty`、`village_id`（滞在村）は維持する。移動・採集・回収・倉庫処理は引き続き未実装。

## 5. 収集・運搬・保管・奉納【基本方針確定／未実装】

- マップ上の神社・ランドマークや対象セルで素材を収集する。狩猟・採集で異なる収穫品、レア・通常品、共通激レア、地域固有品を想定。アイテム種類数や抽選率の詳細は未定。
- 素材を獲得するのは**妖精**。自動的に村へ入ることはなく、獲得した妖精のカバンに保存する。
- カバンの容量は**重量制**。鉱石等を重くすることで、何度も運搬・帰還する価値をつくる。重量・容量の具体値や満杯時の採集判定は未定。
- ユーザーは派遣中も妖精のインベントリの**中身を閲覧可能**。無課金では遠征先でアイテムを廃棄できない。**課金特典利用時のみ遠征先で廃棄可能**とする。
- 荷物を回収できるのは、妖精が**ユーザーの所属村へ帰還したとき**だけ。遠征先の村では回収も奉納もできない。
- **回収したアイテムはユーザー所有の倉庫に保管する**。この倉庫は**重量無制限**であり、妖精の重量制カバンとは別の在庫として管理する。
- **倉庫は所属村ではなくユーザーに紐づく**。ユーザーが所属村を移籍した場合も、倉庫内の素材はすべてユーザーとともに移動する。移籍時の在庫消失、村への預け替え、自動奉納は発生しない。
- 倉庫の素材は**自動奉納しない**。ユーザーが好きなタイミングで任意の素材を選び、**その時点のユーザー所属村**へ手動奉納する。倉庫に長期間保管することもできる。
- **回収の場所はユーザー所属村に帰還した妖精に限る**。帰還後の回収操作を自動にするか手動にするか、ユーザーの移籍途中や妖精の帰還途中に所属村が変わった場合の処理は未決定。
- 奉納できる村は**ユーザー自身の所属村のみ**。奉納元はユーザーの倉庫であり、妖精の遠征カバンから直接奉納しない。妖精が滞在する旅先の村へ納めたり、別の村の精霊樹を直接育てたりはしない。
- 奉納価値はアイテム種類・レア度によって変える。**週替わりで精霊樹が欲しがるアイテムを変える**構想を採用する。倍率、切替曜日／時刻、対象アイテムの選び方は未定。

### 具体的な遊びの例

1. ユーザーは大阪の村に所属する。
2. 妖精Aは遠方の村へ移動し、そこを採集拠点として滞在する。ユーザーの所属村は大阪のまま。
3. 妖精Aが鉱石を採集してカバンを満たし、移動時間をかけて大阪の所属村へ帰還する。
4. ユーザーが荷物を回収し、**ユーザー倉庫**へ保管する。選んだ素材だけを大阪の村の精霊樹へ手動奉納し、残りは倉庫に保存する。
5. その後ユーザーが京都の村に移籍した場合も、**倉庫の在庫はユーザーとともに移動**する。京都の所属村で奉納するか、倉庫に残しておくか選べる。
6. 妖精Aは同じ遠征村に再び向かうか、別の村へ派遣される。

**確認済み実装:** `terrains.default_resources` は存在するが、採集・妖精の重量在庫・ユーザー倉庫・回収・遠征先での廃棄・課金・奉納・精霊樹成長処理は、このZIPの関連コードから確認できない。

## 6. 仲間との探索・収集【構想】

- 仲間と開拓すると獲得通貨・アイテムが増える構想。
- 開拓度への恩恵が高くなる。
- 移動可能距離が伸びる。
- 出発前に30分の準備期間を設け、その間に相乗りメンバーを募集できる。
- メンバー参加により準備期間を短縮する案もある。**必ず30分なのか、短縮可能なのかは要整理。**
- キャラクターの得意分野に応じて追加素材の抽選を行う（詳細は `GAME_RULES.md`）。

**確認済み実装:** 相乗り募集、準備時間短縮、共同収集報酬を処理するAPIは、このZIPでは未確認。

## 7. チャット・交流【方針確定／一部実装】

**チャットの発言主体・個人宛先はユーザー同士**。チャットのための「操作中妖精」は廃止し、保有妖精の増減はチャット相手・過去DMに影響しない。村チャットの権限はユーザーの所属村で判定し、派遣先の妖精には滞在先村のチャット権限を与えない。

| 記号 | 送信範囲 | 現状 |
|---|---|---|
| 指定なし | 現在いる村の人（企画の旧定義。新しいユーザー現在地の扱いは要再検討） | 未対応 |
| `@ユーザー公開ID 本文` | ユーザー宛DM | **今回変更** |
| `*` | 自分の所属する都道府県 | 未対応 |
| `**` | 全体 | 対応 |
| `#` | **ユーザーの所属村** | **今回変更** |
| `##` | 所属村の同盟 | 未対応 |
| `!` | 周囲3マス | 未対応 |
| `!!` | 周囲6マス | 未対応 |

- 茶禁は引き続きユーザー単位。
- 個人DMの公開宛先は **`users.text_id`** を使う。`characters.text_id` は新しい差分migrationで廃止する。
- 実装詳細、旧データとの共存、配信チャンネルは `GAME_RULES.md` / `ARCHITECTURE.md` を参照。

## 8. 通貨・取引・課金【構想】

- 旅をすることでゲーム内通貨が貯まる。
- ゲーム内通貨でアイテムを購入できる。
- アイテム同士／プレイヤー間の取引ができる。
- **取引はサブスクユーザー限定**という案。
- 課金アイテムとして通貨とチケットを想定する。
- キャラクター枠の追加購入を想定する。

**未定:** 通貨と有償通貨の区別、チケット用途、取引相手・手数料・返金・サブスク失効時の扱い、価格の最終決定、決済事業者など。
