# Hivee — ゲーム企画・仕様概要

> 更新日: 2026-11-15  
> 情報源: 開発者がチャットで提示したゲーム構想。**ソースコードに実装されていることを保証する文書ではない。**  
> 用語: **構想**=開発者が目指す仕様、**確認済み実装**=ソースで直接確認、**未定**=詳細が決まっていない。

## 1. コンセプトと世界観【構想】

**Hivee（ハイビー）**は、リアルな地図を舞台にした、協力型の村育成ゲーム。

- 現実の地図にH3の六角形セルを重ね、神社・ランドマークなどを巡ってアイテムを集める。
- プレイヤー同士が協力し、**村ごとの精霊樹**を成長させる。
- 精霊が存在するファンタジー世界観。
- 個人キャラクターの成長よりも、**みんなで村を育てる**遊びを優先する。
- 村同士で資源を奪い合ったり、略奪したりするゲームにはしない。
- 他の村にも収集に行けるが、相手の資源を奪う行為ではない。

### 遊びの中心となる想定ループ【構想の整理】

マップを探索 → ランドマーク／対象セルで狩猟・採集 → 獲得素材をキャラクターのインベントリに保管 → 所属村へ手動で奉納 → その村の精霊樹の成長に貢献 → 旅や仲間との探索につなげる。旅先で収集した素材を持ち帰り、地元の村に奉納する遊びも中心体験とする。

*これは開発者の説明を整理したもので、進行順序・UI・クエスト設計がすべて確定したわけではない。*

## 2. マップ・探索【構想】

- H3による六角形セルを地図に配置する。
- 原則として**全マップを航行可能**とし、海や山は移動コストを相当に高くする。
- セルごとに「開拓度」があり、繰り返し訪問すると通過係数が下がって移動しやすくなる。
- 行軍値・体力・仲間・装備なども移動に関わる構想。
- 特定の神社、ランドマーク、パワースポットなどに固有の報酬を置く構想。

**確認済み実装:** `resources/js/pages/world/` にMapLibreとH3の描画・選択処理がある。`villages` / `terrains` / `village_neighbors` にH3セル・地形・隣接情報の土台がある。**移動・開拓値更新・経路探索の完成は、このZIPから確認できない。**

## 3. 村と精霊樹【構想】

- プレイヤーは村に所属する。
- 村単位で精霊樹を育てる。
- 仲間・村人・同盟のコミュニケーションを用意する。
- 村ごとに外観・デザインを切り替える構想がある。
- 村同士の資源略奪はしない。
- キャラクターは所属村を別の村へ移籍できる。旅先で活動するために一時的に移籍し、その後地元の村へ再移籍することもできる。
- 素材の奉納先は、**奉納操作時点でキャラクターが所属している村**。単に地図上でその村の近くにいるだけで奉納先が切り替わるわけではない（実際に村へ到着する必要があるかなど、場所の制約は未決定）。
- 「地元の村」はプレイヤーが戻りたい村を指す説明上の呼称。移籍後も維持する別の本籍・ホーム村データが必要かは未決定。

**確認済み実装:** `characters.village_id` が `villages.id` を参照するmigrationがある。現行の `villages` が地図セルも表現しているため、**「所属村」と「地理的セル」の関係は要設計確認**。精霊樹の成長ロジックは未確認。

## 4. キャラクター【構想】

- 複数のキャラクターを持てる。最大3枠。
- 1枠目を基本とし、2枠目は1,500円、3枠目は3,500円、2・3枠のセット購入は4,500円という案。
- **狩猟キャラクター**: 素材収集時間を10%短縮。
- **採集キャラクター**: 素材のレア獲得率に10%の恩恵（増加方式は未定）。
- キャラクターには体力があり、移動できる距離に関係する。
- 仲間との行動で移動距離が伸びる。

**確認済み実装:** `characters` のDBスキーマ、`Character` Model、`CharacterSpecialty`（狩猟=1、採集=2）、`users.active_character_id` がある。**枠課金、体力計算、能力効果の適用APIは未確認**。

## 5. アイテム・収集【構想】

- マップ上の対象地点を訪問するとアイテムが獲得できる。
- 狩猟キャラと採集キャラで獲得できる素材を分ける。
- それぞれレア・ノーマルの種類を用意（元の説明は「それぞれレア・ノーマルアイテム4種」。**4種が合計か各区分かは要確認**）。
- 共通の激レアアイテム1種を想定する。
- 特定地点にだけ存在する固有アイテムも用意する。
- 課金によるオリジナルアイテム制作を想定する。
- 他の村に収穫に行っても、それは略奪ではなく収集である。
- 各キャラクターはカバンに相当する**インベントリ**を持ち、狩猟・採集で得たアイテム／素材を保持して持ち運べる。
- 収穫品は**自動的に村へ納入されない**。獲得時点ではキャラクターのインベントリに入り、プレイヤーが選択して手動で奉納したときに初めて村へ渡る。
- 未奉納の収穫品は村を移籍してもキャラクターに残り、旅先から地元へ持ち帰れる。奉納した分だけインベントリから減り、奉納先の村の精霊樹の育成に寄与する。

### 旅先で収穫し、地元に奉納する体験【今回追加した基本方針・未実装】

1. キャラクターが旅先の村に移籍する。
2. 旅先の周辺で狩猟・採集を行い、収穫品を自分のインベントリに貯める。
3. 奉納せずに地元の村へ戻り、再度その村に移籍する。
4. インベントリ内の収穫品を選んで地元の村へ**手動奉納**する。
5. 奉納先の村の精霊樹の成長に貢献する。

*移籍とマップ移動の関係、移籍回数・待機時間、容量、奉納量と精霊樹成長の換算は未決定。上記はゲーム体験と所有・奉納先の基本方針であり、既存APIで遊べることを意味しない。*

**確認済み実装:** `terrains.default_resources` カラムはある。独立したアイテム在庫・抽選・訪問報酬API、インベントリ、移籍、奉納、精霊樹への反映処理は、このZIP内では確認できなかった。

## 6. 仲間との探索・収集【構想】

- 仲間と開拓すると獲得通貨・アイテムが増える構想。
- 開拓度への恩恵が高くなる。
- 移動可能距離が伸びる。
- 出発前に30分の準備期間を設け、その間に相乗りメンバーを募集できる。
- メンバー参加により準備期間を短縮する案もある。**必ず30分なのか、短縮可能なのかは要整理。**
- キャラクターの得意分野に応じて追加素材の抽選を行う（詳細は `GAME_RULES.md`）。

**確認済み実装:** 相乗り募集、準備時間短縮、共同収集報酬を処理するAPIは、このZIPでは未確認。

## 7. チャット・交流【構想】

送信先を先頭の記号で指定する方式を想定。

| 記号 | 送信範囲の構想 |
|---|---|
| 指定なし | 現在いる村の人 |
| `@` | 個人 |
| `*` | 自分が所属する都道府県 |
| `**` | 全体 |
| `#` | 自分の所属村 |
| `##` | 所属村の同盟 |
| `!` | 周囲3マス |
| `!!` | 周囲6マス |

チャット内容により発言禁止（茶禁）にする機能を想定する。

**確認済み実装:** DB・enumは8種類の型を持つが、現在のチャット送信APIの主要対応は全体 `**` と個人 `@公開キャラクターID`。チャットの現在の状況と注意点は `GAME_RULES.md` / `ARCHITECTURE.md` を参照。

## 8. 通貨・取引・課金【構想】

- 旅をすることでゲーム内通貨が貯まる。
- ゲーム内通貨でアイテムを購入できる。
- アイテム同士／プレイヤー間の取引ができる。
- **取引はサブスクユーザー限定**という案。
- 課金アイテムとして通貨とチケットを想定する。
- キャラクター枠の追加購入を想定する。

**未定:** 通貨と有償通貨の区別、チケット用途、取引相手・手数料・返金・サブスク失効時の扱い、価格の最終決定、決済事業者など。
